Fragment order
--------------

directory and list them in this exact order in the kernel_aarch64
defconfig_fragments list in common/BUILD.bazel:

Kleaf recipe
------------
Inside define_common_kernels, the kernel_aarch64 target carries:

    "defconfig_fragments": [
        "docker_systemd_v2.fragment",
        "sysvipc.fragment",
        "sukisu.fragment",
        "susfs.fragment",
        "kpm.fragment",
        "usb_extra.fragment",
        "extras_net.fragment",
        "extras_ipset.fragment",
        "extras_criu.fragment",
        "extras_fs.fragment",
        "extras_rndis.fragment",
        "extras_zramwb.fragment",
        "extras_zswap.fragment",
        "nextmax_nft_bridge.fragment",
        "nextmax_ipvlan.fragment",
        "nextmax_nft_modules.fragment",
        "maxest_extra1.fragment",
        "maxest_cgroups.fragment",
        "maxest_fanotify.fragment",
        "maxest_synproxy.fragment",
        "maxest_extra3.fragment",
        "maxest_extra4.fragment",
        "forsen.fragment",
    ],

Kleaf applies these after gki_defconfig, in list order. Do not edit
arch/arm64/configs/gki_defconfig; Kleaf's check_defconfig rejects it.

The maxest source patch series in patches/maxest/ must be applied before the
build. Several fragments select features whose kernel-side layout is only
ABI-safe once those relocations are present.

Authoritative config
--------------------
configs/maxest.config is the .config produced by the recorded build
(sha256 96e6825461eba8795cd4abc378396259104cb020a99a15fa79e3375902d8c61e,
218,830 bytes). It is the authoritative description of the built kernel.

The fragments and their order are the input recipe used for that build. If the
fragment list and the recorded config ever disagree, the config and the
recorded artifact hashes are the reference.

Not part of the final recipe
----------------------------
nextmax_nft.fragment (NF_TABLES core only) was an ABI-isolation experiment and
is deliberately not in the ordered list above. nextmax_nft_bridge.fragment
enables the same core option together with BRIDGE_NETFILTER for the final
build.

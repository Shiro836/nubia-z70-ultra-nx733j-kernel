# Building the kernel

The build is a standard Kleaf/GKI build with one pinned commit, one pinned
toolchain and a variant-dependent fragment list.

## 1. Tree

The target is the AOSP common kernel at commit
`3637f4904cf55eb3e7eccb9d747d754a4e199740`, on branch `android15-6.6`. The
`repo` manifest used is the standard `kernel/manifest` `default.xml`
(`default revision="main-kernel-build-2024"`, superproject
`kernel/superproject` revision `common-android15-6.6`).

The checkout must be shallow or tagless, as the original build was. If a usable
`v6.6.92` tag is present, `scripts/setlocalversion` emits a commit count instead
of the required `-g3637f4904cf5` suffix.

```bash
repo init -u https://android.googlesource.com/kernel/manifest -b common-android15-6.6
repo sync -c -j8
git -C common checkout 3637f4904cf55eb3e7eccb9d747d754a4e199740
```

Kleaf `build/kernel` must be at `b5e2a413b0d6b44a66fb6eb352da2ed42c0477f8`
(2025-08-14). The version string, build flags and embedded metadata depend on
it.

## 2. Toolchain

Use only the prebuilts that ship with that Kleaf revision:

- clang-r510928 (Android clang 18.0.0, build 11368308), LLD 18.0.0
- pahole v1.25 from `prebuilts/kernel-build-tools`
- the bundled Bazel via `tools/bazel`

Do not replace them with host `clang`, `ld`, `objcopy` or `pahole`. BTF is
allocated and present in `Image`, so the pahole version is part of the output.

## 3. Fragments

Kleaf selects fragments through `defconfig_fragments` in
`common/BUILD.bazel`:

```python
define_common_kernels(target_configs = {
    "kernel_aarch64": {
        "kmi_symbol_list_strict_mode": True,
        "defconfig_fragments": ["docker_systemd_v2.fragment", "sukisu.fragment"],
        ...
```

Variant mapping:

| Variant | Value |
|---|---|
| stock | line omitted |
| sukisu_only | `["sukisu.fragment"]` |
| full | `["docker_systemd_v2.fragment", "sukisu.fragment"]` |
| docker_only (control) | `["docker_systemd_v2.fragment"]` |

`scripts/build-kernel.sh` rewrites this line for the requested variant and
restores the original `BUILD.bazel` on exit. If you edit it by hand, keep the
file backed up.

Do not hand-edit `arch/arm64/configs/gki_defconfig`; Kleaf's
`check_defconfig` rejects it. Use fragments.

## 4. Build

```bash
cd <gki-tree>
BUILD_NUMBER=13944661 ./tools/bazel build --config=android_ci //common:kernel_aarch64
```

Outputs:

- `bazel-bin/common/kernel_aarch64/Image`
- `bazel-bin/common/kernel_aarch64/Module.symvers`
- `bazel-bin/common/kernel_aarch64_config/out_dir/.config`
- `bazel-bin/common/kernel_aarch64/modules_staging_dir.tar.gz` (signed GKI modules)

The `Image` is memory-comparable with the stock one; do not compare
`bazel-bin/common/kernel_aarch64/Image.gz` or other compressed variants.

### Clean builds after a config change

Bazel can reuse pre-config objects from DDK/test packages after a fragment
change. That produced 65 false CRC mismatches in an earlier experiment: the
kernel had the new config while some modules were still built against the old
one. Run a clean build (`./tools/bazel clean`, or prove every module
recompiled) before gating a new configuration. Incremental results are not
trusted after config changes.

## 5. Module-signing certificate (exact stock equality)

The kernel build generates a random RSA key and embeds its certificate in the
`Image` (`system_certificate_list`). The stock `Image` contains the OEM/GKI
certificate instead. Reproducing the stock `Image` byte for byte therefore
requires injecting that public certificate at build time.

Recorded reference certificate: DER sha256
`f24e19401d2edce015dcdbba4264d6f3117f250b1b6ad78e8609fecf950f4301`, subject
`CN=Build time autogenerated kernel key`, serial `5C57A2C5...`, notBefore
2025-08-16 00:15:48 GMT. It is a public certificate; the corresponding private
key is not recoverable and is not needed. It can be located inside a stock
`Image` as the DER X.509 blob in the built-in certificate list; ASN.1 tooling
(`openssl asn1parse`, a DER sequence scanner) can extract it. Verify the sha256
before using it.

Procedure (build-only, not committed):

1. Save the recovered certificate as DER and convert it to PEM:
   `openssl x509 -inform DER -in gki_cert.der -out gki_cert.pem`.
2. Generate a throwaway local RSA-4096 key:
   `openssl genrsa -out local_signing.key 4096`.
3. Concatenate the certificate and the key into
   `common/certs/gki_signing_key.pem`. `extract-cert` reads the certificate;
   `sign-file` uses the key only to sign modules. The bytes embedded in the
   kernel are the stock certificate.
4. In `common/certs/Makefile`, replace the key-generation command with:
   `cmd_gen_key = cp $(srctree)/certs/gki_signing_key.pem $@`.
5. Keep the tree clean for `setlocalversion`: add
   `certs/gki_signing_key.pem` to `.git/info/exclude` and mark the Makefile
   `git update-index --assume-unchanged certs/Makefile`.

Never commit the private key. If the certificate is omitted, the build still
works; the `Image` differs from stock only in the embedded certificate and the
derived `.note.gnu.build-id` (observed: 13 byte ranges, 1,121 bytes, in the
first reproduction attempt).

The recorded variant hashes in the README were produced with this override in
place.

## 6. Version string

The release string is composed as:

- `6.6.92` from the kernel `Makefile`
- `-android15-8` from `build.config.common` (`KMI_GENERATION=8`)
- `-g3637f4904cf5` from `scripts/setlocalversion` (12 hex digits)
- `-ab13944661` from `BUILD_NUMBER`
- `-4k` from `CONFIG_LOCALVERSION`

Stock release:

```
6.6.92-android15-8-g3637f4904cf5-ab13944661-4k
```

Variants built with an untracked `drivers/kernelsu/` include `-dirty`:

```
6.6.92-android15-8-g3637f4904cf5-dirty-ab13944661-4k
```

The timestamp comes from Kleaf's `workspace_status_stamp.py`, which defaults
`SOURCE_DATE_EPOCH` to the commit time.

## 7. Module CRC gate

Build or obtain `Module.symvers`, then check it against the module set that will
load on the device:

```bash
KERNEL_SRC=<gki-tree> python3 -I scripts/crc_check.py \
  <out>/Module.symvers \
  /path/to/vendor_dlkm /path/to/system_dlkm /path/to/vendor_boot/lib/modules
```

The script extracts `__versions` with `llvm-objcopy` and distinguishes symbols
exported by the kernel from symbols provided by other modules. Exit code 0
requires zero kernel CRC mismatches and zero symbols missing everywhere.

The stock set used during development contained 680 modules (280 vendor_dlkm,
94 system_dlkm, 306 vendor_boot first-stage), with 37,116 symbol references.
The stock modules are not included in this repository. Supply your own; do not
mix stock and rebuilt modules with a reconfigured kernel.

SukiSU adds no exported symbols, so its `Module.symvers` matches the
corresponding non-KSU build.

## 8. Reproducibility checklist

- `common/` at `3637f4904cf5`, no extra tracked changes, no usable tags.
- `build/kernel` at `b5e2a413...`.
- clang-r510928, LLD 18, pahole v1.25.
- Fragment list exactly as in the variant table.
- `BUILD_NUMBER=13944661`, `--config=android_ci`.
- Signing-certificate override present for exact stock equality.
- Clean build, not an incremental one after a config change.
- Compare the uncompressed `Image`.
